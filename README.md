# PVSE: Identifiable Support Editing

Official research code for **“Identifiable Support Editing: From Hard-Delete Lattices to Patch-Verifiable Reliability.”**

This repository provides the complete runnable implementation and formal
configurations for all experiments reported in the accepted paper. The trained
ResNet-12 backbone checkpoint is distributed through the GitHub Release.
External datasets and the FEAT dependency are accessed through the documented
local-path interfaces.

The repository includes the paper-scoped source code, 14 formal experiment
configurations, submitted supporting artifacts, deterministic tests, and
paper-to-code result traceability.

## Repository contents

| Component | Location |

The reported experiment families are summarized in [`docs/EXPERIMENTS.md`](docs/EXPERIMENTS.md), and each paper item is connected to its configuration, implementation modules, generated outputs, and submitted reference artifacts in [`docs/RESULT_TRACEABILITY.md`](docs/RESULT_TRACEABILITY.md).

## Verification

The release candidate has passed the following checks:

- 47 deterministic unit and protocol-regression tests;
- 121 submitted-artifact byte and SHA-256 checks;
- 52 submitted-result arithmetic and cross-table checks;
- reduced-count real-data execution across every reported experiment family;
- strict ResNet-12 and FEAT checkpoint loading;
- source-tree, configuration, and release-integrity checks.

The real-data verification used real images and the exact checkpoint identities recorded below. It exercises the complete integration path on reduced episode/query counts; the formal configurations in `configs/paper/` retain the paper episode counts and paired episode bootstrap settings. ## Running the paper configurations

Fourteen formal configurations live in `configs/paper/`. They preserve the paper protocol, including 5-way 5-shot episodes, 15 queries per class, 84×84 inputs, logit scale 10, fixed seeds and thresholds, and paired episode bootstrap with 10,000 resamples.

Example:

```bash
export PVSE_MINIIMAGENET_ROOT=/data/miniimagenet
export PVSE_BACKBONE_CHECKPOINT=/assets/backbone_v315_best_for_v316_logreg.pth
export PVSE_OUTPUT_ROOT=/work/pvse
export PVSE_DEVICE=cuda
pvse-run-config configs/paper/clean_table4.yaml
```

Table 9 reuses the clean verifier generated by the Table 4 run. Set `PVSE_CLEAN_VERIFIER_BUNDLE` to the resulting `clean_verifier.joblib` before executing `configs/paper/external_table9.yaml`.

## Protocol notes

- Test labels and corruption masks are analysis fields, not inference features.
- The main contamination protocol uses within-episode other-class copy/replacement, with all targets sampled before sources.
- Confidence intervals use paired episode resampling rather than individual-query resampling.
- Generated local manifests and indexes may contain machine-specific paths and should remain in local run directories.
